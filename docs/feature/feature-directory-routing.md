# multi-claude：按目录自动选账号（`claude-auto`）

> 2026-10-01 注记：plan-review 2 轮收敛，用户同意编码；代码已按方案实现，待独立代码评审与编译机验证，未提交。来源：`docs/analysis/competitor-analysis.md` §6.2 第 1 项。基线：main `3402c25`。用户决定：入口命令为 `claude-auto`（与名为 `auto` 的账号冲突时判冲突）；未匹配时用配置的默认账号，未配置则直接运行 `claude`；规则只存在 `config.json`，不读写项目内的标记文件。

## 1. 背景

目前要用哪个账号，取决于用户输入哪个 `claude-<名称>`。竞品（claude-swap `map`、claude-profile-manager、cprof、dotclaude）普遍支持“按当前目录自动选账号”。本方案在不修改 shell 配置、不碰凭据的前提下补上这一能力：新增一个由配置生成的入口命令 `claude-auto`，启动时按当前目录选出账号，再转交给该账号的 `claude-<名称>`。

## 2. 目标 / 非目标

**目标**

1. `config.json` 新增路由规则（目录 → 账号）与可选的默认账号；命令 `route` 增删规则、设置默认账号，`which` 显示某目录会用哪个账号。
2. 生成 `<bin_dir>/claude-auto`：按“当前目录的物理路径落在哪条规则目录之下、取最长匹配”选账号，转交给该账号的启动命令；无匹配时用默认账号，未设默认账号时直接运行 `claude`。
3. `list`（含 `--json`）、`doctor`、补全覆盖路由。

**非目标**

- cd 钩子、改写 shell 配置、让裸 `claude` 命令自动路由。
- 项目目录里的标记文件（如 `.claude-account`）。
- 按 git 仓库根精确匹配：仓库根目录作为路径前缀规则即可覆盖。
- VS Code `processWrapper` 入口（分析文档 §6.4 待定项）。

## 3. 假设与约束

- `claude-auto` 是 POSIX sh，0755，与账号启动命令同目录、同样由配置推导；内容相同即 `unchanged`。
- 路径比较用物理路径：当前目录取 `pwd -P`，规则目录在启动时 `cd -P` 后 `pwd -P`；规则目录不存在时该规则被跳过。Python 侧（`which`）用 `os.path.realpath` 实现同一算法。
- 前缀判定按路径段：当前目录等于规则目录，或位于其下（`"$here/"` 以 `"$r/"` 开头）。`/work` 不匹配 `/workshop`。
- 多条规则同时匹配时取物理路径最长的；长度相同时取配置中靠前的一条（sh 与 Python 都用“严格大于才替换”）。
- 规则目录不能是 `/`（会匹配一切，与默认账号语义重复）。
- `claude-auto` 用绝对路径调用 `<bin_dir>/claude-<名称>`，不经 `PATH` 查找，避免被同名文件遮住。

## 5. 方案

### 5.1 实现要点

#### 5.1.1 配置

```json
"routes": {
  "default": "main",
  "rules": [
    {"path": "~/work", "account": "work"},
    {"path": "/Volumes/data/client-a", "account": "client-a"}
  ]
}
```

- 字段缺省为 `{"default": null, "rules": []}`；`to_dict` 始终写出 `routes`。
- `parse_config` 只做形状校验，任何不合法内容抛 `ConfigError`（命令行返回 1）：`routes` 必须是对象；`default` 为 null 或合法账号名格式的字符串；`rules` 为列表，每项恰有 `path`（非空字符串）与 `account`（合法账号名格式）；`path` 经 `expand` 后必须是绝对路径且不是 `/`；同一 `expand(path)` 不能出现两次。
- “规则引用的账号必须已登记”不在解析时校验，而在收敛计划中判冲突（§5.1.3），这样 `remove` 与 `apply -f` 得到同样的退出码 3。
- `Config` 存 `route_rules: List[RouteRule]`（`NamedTuple(path, account)`，`path` 保持用户写法）与 `route_default: Optional[str]`。

`claude-auto` 内容（所有路径经 `shlex.quote`）：

```sh
#!/bin/sh
# managed-by: multi-claude router
# Generated by multi-claude. Do not edit; use `multi-claude route` to change it.
here=$(pwd -P) || exit 1
target=''
best=0
# 每条规则一段；r 为规则目录的物理路径，目录不存在时为空、不参与匹配
r=$(cd -P -- '/Users/x/work' 2>/dev/null && pwd -P) || r=''
if [ -n "$r" ]; then
  case "$here/" in
    "$r"/*) if [ "${#r}" -gt "$best" ]; then best=${#r}; target='/Users/x/.local/bin/claude-work'; fi ;;
  esac
fi
# ……其余规则……
if [ -z "$target" ]; then
  target='/Users/x/.local/bin/claude-main'   # 有默认账号时；没有时整行为 target=''，走下面的 claude 分支
fi
if [ -n "$target" ]; then
  exec "$target" "$@"
fi
if ! command -v claude >/dev/null 2>&1; then
  echo "multi-claude: claude not found in PATH" >&2
  exit 127
fi
exec claude "$@"
```

- 没有规则（只有默认账号）时省略 `here=…` 与 `best=0` 两行及全部规则段，直接走默认账号分支；否则 shellcheck 会报变量未使用。
- 规则目录写入的是 `expand(rule.path)`（只展开 `~`、不 realpath），物理路径在启动时求得，所以规则目录事后变成软链也能正确匹配。
- 目标启动命令写绝对路径 `launcher.launcher_path(expand(bin_dir), 账号名)`：账号名取 `config.find(rule.account).name`（实际大小写）；找不到时（用户手工改了 `config.json`）原样用 `rule.account`，渲染不抛异常，由 `apply` 判冲突、`doctor` 报 `route-account`。
- 受管标记固定为 `# managed-by: multi-claude router`。

#### 5.1.3 收敛计划（`accounts.plan`）

在 `accounts.py:114` 计算 `config_changed` 之前追加：

1. **路由是否启用**：`new.route_rules` 非空或 `new.route_default` 非空。
2. **账号存在性冲突**：每条规则的 `account` 与 `route_default` 必须能 `new.find` 到，否则追加 `CONFLICT config`，原因 `route <path> uses account <name>, which is not registered; run multi-claude route <path> --remove first`（默认账号：`run multi-claude route --no-default first`）。
3. **名称冲突**：路由启用且 `new.find("auto")` 不为空时，追加 `CONFLICT launcher <bin>/claude-auto`，原因 `claude-auto is the directory router; an account named 'auto' cannot coexist with routes`。
4. **入口文件**：路径 `P = <expand(new.bin_dir)>/claude-auto`。
   - 路由启用：`P` 不存在 → `CREATE`；是普通文件且第 2 行为路由标记 → 内容相同且可执行为 `UNCHANGED`，否则 `UPDATE`；其它情况（非受管文件、目录、软链、账号启动命令）→ `CONFLICT`，原因 `already exists and is not the multi-claude router`。
   - 路由未启用：`P` 是路由受管文件 → `DELETE`（原因 `no routes configured`），否则不动。
   - `bin_dir` 变化时，旧目录下的路由受管文件 → `DELETE`（原因 `bin_dir changed`）。
5. 写文件沿用 `_write_launcher`（`accounts.py:197`）的原子写与 0755。

`apply -f` 文件中未登记的 `identity: default` 账号按 v0.1 规则被跳过（`cli.py` `_load_apply_file`）时，引用它的路由规则与默认账号也一并跳过，逐条输出 `skip route <path> (account <name> is skipped; set it again with ...)` / `skip default route (...)`，不判冲突；否则带路由的配置文件在新机器上整条 `apply` 都会失败。

`apply` 的孤儿清理（`scan_managed`）只识别账号标记，不会误删 `claude-auto`；反之路由计划只认路由标记，不会误删账号启动命令。

#### 5.1.4 命令行

| 命令 | 作用 | 退出码 |
| ---- | ---- | ---- |
| `route PATH NAME [--dry-run]` | 新增规则，或把已有规则（按 `expand` 后的路径比较）改指 NAME | 0；NAME 未登记 1；参数错误 2；冲突 3 |
| `route PATH --remove [--dry-run]` | 删除规则；规则不存在时输出 `PATH has no route` 并返回 0 | 0 |
| `route --default NAME [--dry-run]` | 设置默认账号 | 0；未登记 1 |
| `route --no-default [--dry-run]` | 清除默认账号 | 0 |
| `which [DIR]` | 只读：输出 DIR（缺省为当前目录）会用哪个账号以及命中的规则 | 0；DIR 不存在 1 |

- `route` 的四种形式互斥，argparse 无法表达的组合（如同时给 NAME 与 `--remove`、什么都不给）在 `dispatch` 中判为 `UsageError`（2）。
- `PATH` 经 `routes.normalize_path(raw, os.getcwd())` 规范化后存储；目录当前不存在时照常写入并输出警告 `PATH does not exist; the route is ignored until it does`。
- `which` 的输出：`work (route ~/work)`、`main (default)` 或 `claude (no route, no default)`，均返回 0；命中的规则或默认账号引用了未登记账号（只会出现在手工改过的配置里）时输出 `<名称> (not registered; run multi-claude doctor)` 并返回 1；DIR 支持 `~`；`which` 也走 `main` 中 list / usage 那段只读分派（不加锁、迁移未完成时放行）。

#### 5.1.5 `list`

- 表格之后（`cli.py:468` 默认账号注记之前）在路由启用时输出：

  ```text
  routes:
    ~/work -> work
    /Volumes/data/client-a -> client-a
    (default) -> main
  ```

  未启用时不输出任何路由内容，v0.2 的表格输出保持不变。
- `--json` 顶层增加 `"routes": {"default": "main" | null, "rules": [{"path": "~/work", "account": "work", "exists": true}]}`，`exists` 为规则目录当前是否存在；配置不存在时 `routes` 为 `{"default": null, "rules": []}`。`schema_version` 仍为 1（字段只增不删）。

路由启用时追加：

| `router` | `claude-auto` | 缺失、内容过期或被非受管文件占用（修复：`multi-claude apply`） | — |

#### 5.1.7 补全

`completion.py` 的 `NAME_COMMANDS`（:16）改为“子命令 → 各位置参数的候选类型”表，`PATH_OPTIONS`（:18）旁增加“选项 → 值的候选类型”表：

```python
POSITIONAL_KINDS = {"migrate-default": ["name"], "add": ["name"], "proxy": ["name", "proxy"],
```

## 6. 备选方案与决策

- **cd 钩子 / shell 函数让裸 `claude` 自动路由**：需要改用户的 shell 配置，违反现有非目标；`claude-auto` 是显式入口，用户可自行把别名指向它。
- **git 仓库根精确匹配**：多一个外部依赖（`git`），仓库根目录写成路径规则即可。
- **把规则目录在生成时 realpath 写死**：规则目录事后变成软链或被替换时会失配；启动时求物理路径多几次 `cd -P`，代价可忽略。
- **项目内标记文件**：用户决定不做。

## 7. 影响分析

**正向推**

- `plan` 新增的路由动作只在路由启用或残留路由入口时出现；未使用路由的用户，`plan` 输出与 v0.2 完全相同（回归 §8 第 9 条）。
- `claude-auto` 只转交给已生成的账号启动命令，账号启动命令的内容与登录绑定不受影响。
- `remove NAME`、`apply -f` 在账号仍被规则引用时由原来的成功变为冲突 3，这是本方案有意引入的新约束。
- `list --names`（补全依赖）不变。

**反向推**

- 账号孤儿清理 `scan_managed`（`launcher.py:179`）只认 `account=` 标记：已核 `managed_account`（`launcher.py:163-176`）取第 2 行 `MARKER_PREFIX` 之后的内容，路由标记 `# managed-by: multi-claude router` 不以 `MARKER_PREFIX`（`# managed-by: multi-claude account=`）开头，返回 None，不会被当成账号启动命令删除。
- 账号 `auto` 的启动命令路径与 `claude-auto` 相同：两者不可共存，由 §5.1.3 第 3 条在计划阶段拦下，任何文件都不会被覆盖。
- `bin_dir` 变化时账号启动命令已有迁移逻辑（`accounts.py:93-95`），路由入口按 §5.1.3 第 4 条同步迁移。

**运行时**

- 每次运行 `claude-auto`：一次 `pwd -P`，每条规则一次 `cd -P` 子 shell；规则通常个位数，毫秒级。
- 不新增常驻进程，不联网，不读凭据。

**部署形态**

- 规则目录在可移动磁盘上、当前未挂载：该规则被跳过，落到默认账号或 `claude`；`doctor` 给 `route-path` 警告。
- 降级到 v0.2 及更早版本：能加载带 `routes` 的配置，但任何写命令都会把 `routes` 丢掉，`claude-auto` 留在原处继续按旧规则工作。README 的升级说明写明“降级前先 `route --no-default` 并逐条 `--remove`，或手工删除 `claude-auto`”。

## 8. 回归测试

沿用 `tests/helpers.py` 的安全闸。`claude-auto` 的行为用假 claude 观察最终收到的 `CLAUDE_CONFIG_DIR` 与参数判断落到哪个账号。

1. **配置校验**：`routes` 非对象、`rules` 非列表、缺 `path` / `account`、相对路径、`/`、重复路径、`default` 非法 → `apply -f` 返回 1，文件系统不变；缺省 `routes` 的旧配置正常加载，`to_dict` 写出空 `routes`。
2. **route 命令**：新增、改指、删除、设置与清除默认账号各执行两次，第二次全部 `unchanged`；`~/x` 保持写法、相对路径转绝对、尾部 `/` 去掉；目录不存在时警告但写入；NAME 未登记返回 1；`route` 无参数、同时给 NAME 与 `--remove` 返回 2；`--dry-run` 不写任何文件。
3. **冲突与跳过**：`apply -f` 文件含未登记的 `identity: default` 账号且路由（规则与默认账号）引用它 → 账号与这些路由都被跳过并输出 skip 行，退出码 0，其余规则照常生效；`remove work` 而规则仍引用 work → 3，`claude-auto` 与配置不变；`apply -f` 去掉被引用账号 → 3；已有账号 `auto` 时添加规则 → 3；已有规则时 `add auto` → 3；`claude-auto` 是用户自己的文件 → 3。
4. **匹配**：
   - 规则目录本身与其子目录命中；`/x/work` 不命中 `/x/workshop`；
   - 两条嵌套规则取最长；同一物理目录的两种写法（软链与目标）取配置中靠前的；
   - 规则目录是软链、当前目录经软链进入：都按物理路径正确匹配；
   - 路径含空格与单引号；
   - 规则目录不存在：被跳过；
   - 对每个场景，`which DIR` 的输出与在 DIR 下运行 `claude-auto` 实际落到的账号一致（sh 与 Python 两套实现对拍）。
5. **兜底**：无匹配且有默认账号 → 默认账号；无默认账号 → 直接运行 `claude`（假 claude 看到的 `CLAUDE_CONFIG_DIR` 为父环境原值）；`PATH` 中没有 claude → 127。
6. **参数透传**：`claude-auto "a b" -p` 原样传给目标账号启动命令，并排在账号固定参数之后。
7. **入口文件生命周期**：清空规则与默认账号后 `claude-auto` 被删除；`init --bin-dir` 后在新目录生成、旧目录删除；`apply` 不把 `claude-auto` 当孤儿删除；手工改动 `claude-auto` 后 `list` / `doctor` 报过期，`apply` 修复。
8. **list / doctor / 补全**：`list` 路由段与 `--json` 的 `routes`（含 `exists`）；`doctor` 的 `router` error、`route-path` warn，以及手工把规则改成引用未登记账号后 `route-account` error 且 `claude-auto` 渲染不崩；bash 补全 `route ` 后给目录、`route DIR ` 后给账号名、`route --default ` 后给账号名、`which ` 后给目录；既有子命令补全结果不变（v0.2 用例全部通过）。
9. **回归**：v0.2 全部用例通过；未配置路由时 `list` 表格、`apply` 输出与 v0.2 一致；shellcheck 检查含 0 条、1 条、多条规则以及有无默认账号的 `claude-auto`。

## 9. 日志 / 观测点

- `route` / `apply` 的动作行沿用 `[multi-claude] create|update|delete launcher <bin>/claude-auto`。
- `which` 是排查“为什么用了这个账号”的入口；`claude-auto` 运行时不输出任何内容（不干扰 `claude` 的输出）。
- `doctor` 的 `router`、`route-path`。
