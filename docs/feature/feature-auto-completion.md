# 安装与升级后自动启用 Tab 补全

## 1. 背景

`multi-claude completion <shell>` 只把补全脚本打印到标准输出，不写任何文件（`src/multi_claude/cli.py:718-720`）。现有说明和帮助都要求用户把脚本手工写进某个文件：

- README 的“诊断与补全”一节：`README.md:519-522`、`README.zh-CN.md:511-514`；
- `completion` 子命令的帮助示例：`src/multi_claude/cli.py:286-290`。

这些写法保存的都是一份快照，每次升级后都要重新执行一次（`README.zh-CN.md:517`）。安装脚本 `install.sh` 完全不处理补全；它在结尾只提示怎样把 bin 目录加进 PATH，不改用户的配置文件（`install.sh:295-315`）。

用户要求：安装或升级 multi-claude 后就能直接用 Tab 补全，不需要再手工安装。用户已确认的做法是：安装脚本默认往用户的 shell 配置文件里加入补全设置，并提供关闭的方法。

## 2. 目标 / 非目标

**目标**

1. 新增 `multi-claude completion --install [SHELL]` 和 `--uninstall [SHELL]`。安装时写入的设置在每次打开终端时现场生成补全脚本，所以不管以后用哪种方式升级，补全都会自动更新。
2. `install.sh` 在安装或升级的最后自动执行一次安装补全，用户可以用 `--no-completion` 或 `MULTI_CLAUDE_NO_COMPLETION=1` 关闭。用户执行过 `completion --uninstall` 之后，再次运行 `install.sh` 不会把设置加回来。
3. `install.sh --uninstall` 卸载程序时，一并移除安装脚本加入的补全设置。

**非目标**

- 不改补全脚本本身的内容（`src/multi_claude/completion.py` 的 `render`）。
- pipx 和 Homebrew 没有可靠的“装完后执行”入口（Homebrew 公式在另一个仓库），所以这两种安装方式不做自动处理。这些用户需要自己执行一次 `multi-claude completion --install`，之后升级不用再管。
- 不清理用户以前手工保存的补全快照文件（如 `~/.local/share/bash-completion/completions/multi-claude`），只在 `--install` 的输出里提示。
- multi-codex 是否同步另行决定。

## 3. 假设与约束

- **按哪个 shell 安装**：未指定 SHELL 时，Windows 取 `powershell`，其它系统取 `os.environ.get("SHELL")` 的文件名。环境变量未设置或不认识的 shell：不带 `--auto` 的 `--install` 和 `--uninstall` 报错退出 2；`--install --auto` 只打一行提示，退出 0；`--uninstall --auto` 不看 `$SHELL`（见 §5.1 `targets`）。
- **配置文件的位置**：

| shell | 写入位置 | 方式 |
| ---- | ---- | ---- |
| zsh | `${ZDOTDIR:-$HOME}/.zshrc` | 追加带标记的块 |
| bash | macOS 用 `~/.bash_profile`，其它系统用 `~/.bashrc`（与 `shellpath.py:26-28` 同一张表）。macOS 上 `.bash_profile` 不存在、而 `.bash_login` 或 `.profile` 存在时不新建，见下文“不新建配置文件的情况” | 追加带标记的块 |
| fish | `${XDG_CONFIG_HOME:-~/.config}/fish/completions/multi-claude.fish` | 整个文件由本工具管理 |
| powershell | Windows PowerShell 5.1（`powershell`）和 PowerShell 7（`pwsh`）中本机装了的每一个，各自的“当前用户当前主机” `$PROFILE`；查询方法见下文“PowerShell 配置文件的查询” | 追加带标记的块，保持原文件编码 |

- **带标记的块**：

```text
# >>> multi-claude completion >>>
...
# <<< multi-claude completion <<<
```

  - 文件里已有这个块时，原地替换块内的内容，内容相同则报 unchanged。已有块时一律按块处理，下面两条块外的判定只在没有块时进行。
  - **用户自己加的现场生成设置**：块外有现场生成式的调用时，不再加块，状态为 `present`，退出 0。
    - 现场生成式指含以下任一写法：`$(multi-claude completion`、`<(multi-claude completion`、`multi-claude completion <shell> |`。
    - 判断时跳过去掉前导空白后以 `#` 开头的注释行。
  - **旧快照**：块外有补全脚本的首行注释 `(generated by \`multi-claude completion`（`completion.py:191`、`:274`、`:435`）时，说明是以前按 README 整段粘进来的快照。
    - 处理：照常在文件末尾加块，状态为 installed，并多打一行提示，请用户删除旧快照。
    - 为什么可以这样做：块在快照之后执行，zsh 的 `compdef`、bash 的 `complete`、PowerShell 的 `Register-ArgumentCompleter` 都是后注册的生效（zsh、bash 已实测；PowerShell 未实测，若不成立，后果只是旧快照仍在起作用，用户按提示删掉旧快照即可）。所以加块后补全立即是最新的，旧快照只是多余。
    - 快照没有结束标记，不替用户删。
  - **fish 的文件**：fish 的文件路径与旧的快照路径相同（`cli.py:289`），按文件内容区分三种情况：
    - 第一行是固定的标记注释 `# managed-by: multi-claude completion --install`：由本工具管理。按标记判断，不比较全文，所以以后版本改了文件内容也能识别。安装时内容相同报 unchanged、不同就替换；卸载时删除；
    - 首行带 `generated by` 注释：是旧快照，备份后替换；
    - 其它内容：视为用户自己的文件，不改动，状态为 `present` 并打提示；卸载时同样不删，状态同为 `present`。
    - 卸载删除托管文件前同样先备份。
- **块内的写法**（核心约束是：命令找不到、zsh 没有初始化补全时，都不能在打开终端时报错）：
  - zsh：

```zsh
_mc_bin=${commands[multi-claude]:-'<安装时的绝对路径>'}
if [[ -x $_mc_bin ]]; then
  (( $+functions[compdef] )) || { autoload -Uz compinit && compinit -i; }
  eval "$("$_mc_bin" completion zsh)"
fi
unset _mc_bin
```

  需要绝对路径兜底的原因：安装目录不在 PATH 上时，install.sh 会提示用户把 PATH 设置追加到 `.zshrc`（`install.sh:296-315`）。这行设置会落在补全块之后，执行到补全块时 PATH 里还没有 multi-claude。

  - bash：除了 PATH 设置排在块后，还有一种情况：Ubuntu 的 `~/.profile` 先读 `.bashrc`，后把 `~/.local/bin` 加进 PATH。所以在登录 shell 里，`command -v multi-claude` 会找不到命令（2026-11-05 在编译机实测）。为此块内同样写入绝对路径作兜底：

```bash
_mc_bin=$(command -v multi-claude 2>/dev/null || echo '<安装时的绝对路径>')
[ -x "$_mc_bin" ] && eval "$("$_mc_bin" completion bash)"; unset _mc_bin
```

  - fish：文件内容为两行，第一行是上面的标记注释，第二行是 `type -q multi-claude; and multi-claude completion fish | source`。fish 在第一次补全这个命令时才读取该文件，读取时现场生成脚本。
  - powershell：

```powershell
if (Get-Command multi-claude -ErrorAction SilentlyContinue) { multi-claude completion powershell | Out-String | Invoke-Expression }
```

- **绝对路径的取法**：
  - 绝对路径按以下顺序取：
    1. 环境变量 `MULTI_CLAUDE_BIN`（install.sh 调用时设为 `$WRAPPER`），用 `os.path.abspath` 转成绝对路径（`install.sh --prefix` 可能给相对路径）；
    2. `platform.which("multi-claude")`。
  - 都取不到时，如果文件里已有的块带兜底路径，就沿用它（避免手动执行时把 install.sh 写好的路径改没）；否则，或路径里有单引号时，zsh 块写空串，bash 块去掉 `|| echo` 兜底，只靠 PATH 查找。
  - 不用 `sys.argv[0]`：通过 wrapper 以 `-m multi_claude` 启动时，它是 `__main__.py` 的路径。
- **关闭标记**：`completion --uninstall`（不带 `--auto`）在 `platform.state_dir()` 下写一个空文件 `completion-off`。`platform.state_dir()` 就是 `config.json` 所在目录（`config.py:209-210`）。
  - `--install --auto` 先看这个文件，存在就跳过（早于判断 `$SHELL`），只输出一行 `completion: skipped-off <关闭标记的路径>`；不带 `--auto` 的 `--install` 会删掉它。
  - `--uninstall --auto`（install.sh 卸载用）不写也不删这个文件。卸载 multi-claude 时配置目录本来就保留，用户“不要补全”的选择也随之保留。
  - 关闭标记的写入或删除与各文件的处理结果无关；只有参数错误（退出 2）时不动它。
- **读写都按字节**（所有 shell 相同）：
  - 读取：按字节读入。开头有 UTF-8 BOM 的，记下后去掉，其余按 UTF-8 严格解码。
  - 解不出时报错退出 1，不改文件。错误信息写明“文件不是 UTF-8 编码，请先另存为 UTF-8 再重试”。例如：Windows PowerShell 5.1 用 `>>` 写出的 UTF-16 文件，或者记事本以 ANSI 编码保存、含中文的文件。
  - 不支持 UTF-16 等其它编码。
  - 换行：文件里有 `\r\n` 就按 `\r\n` 写入块的各行，否则按 `\n`；其余内容按字节原样保留，不做换行转换。
  - 写回：原来有 BOM 就加回 BOM，然后用新增的 `fsutil.atomic_write_bytes(path, data, mode)` 写入。
    - 它与 `atomic_write` 同样是“临时文件 + fsync + os.replace”，只是以二进制写，不经过文本模式的换行转换。
    - 现有的 `atomic_write` 固定按 UTF-8 文本写（`fsutil.py:81`），在 Windows 上会把 `\n` 转成 `\r\n`，所以不用它。
  - 新建的文件用不带 BOM 的 UTF-8，换行用 `\n`。块内容只用 ASCII 字符，5.1 按 ANSI 读取也不会出错。
- **写入目标**：
  - 先用 `os.path.realpath` 解析出真实目标，对真实目标写，这样 dotfiles 仓库的符号链接不会被替换成普通文件；
  - 按原文件权限写回（同 `statusline._save`，`statusline.py:145-150`）；
  - 新建的文件用 0644；所有 shell 的配置文件所在目录不存在时都先创建（由 `atomic_write_bytes` 内的 `os.makedirs` 负责，同 `fsutil.py:78`）。
- **不新建配置文件的情况**（新建反而会出问题时，跳过该文件，状态为 `skipped`，打一行说明，退出 0）：
  - macOS 的 bash：`~/.bash_profile` 不存在，而 `~/.bash_login` 或 `~/.profile` 存在。bash 登录 shell 只读这三个文件里第一个存在的，新建 `.bash_profile` 会让用户原来的那份失效。也不能改写进 `.profile`，因为 sh 也会读它，sh 里没有 `complete`。
  - PowerShell：profile 文件不存在，而该宿主的执行策略是 `Restricted` 或 `AllSigned`。这种情况下新建的 profile 每次打开窗口都会报“禁止运行脚本”。执行策略和 `$PROFILE` 用同一条查询命令一起取出。执行策略为 `Restricted` 时已有的 profile 照常写；为 `AllSigned` 时已有的 profile 也跳过，因为改动会让签名失效、每次打开窗口报错。
- **NUL 字节**：文件含 `\x00` 时按非 UTF-8 处理（退出 1、文件不变），以免把不带 BOM 的 UTF-16 文件误当成 UTF-8 改坏。
- **备份**：改动已存在的文件之前先备份，新建文件不用备份。
  - 备份放在用户给出的路径旁边（即符号链接所在的目录，如 `~/.zshrc.multi-claude-bak.<时间>`），不放进链接目标所在的 dotfiles 仓库。
  - 备份文件名直接调用 `statusline._backup_path(<给出的路径>)` 生成（`statusline.py:153-160`），同一秒内多次执行不会覆盖。
  - 备份内容是真实目标的内容，用 `shutil.copy2(真实目标, 备份)`。
- **PowerShell 配置文件的查询**：
  - 5.1 用 `platform.system_program("powershell.exe")`（`platform.py:280-286`），7 用 `platform.which("pwsh")`。两者都不会执行当前目录里的同名程序。
  - 命令为 `<程序> -NoProfile -NonInteractive -Command "try { [Console]::OutputEncoding = [System.Text.Encoding]::UTF8 } catch {}; $PROFILE; Get-ExecutionPolicy"`，与 `platform.py:821` 的做法相同，路径里有中文时也不会变成乱码。
  - 输出按 UTF-8 解码，去掉开头的 BOM（同 `platform.py:850-855`）。取第一行非空内容为路径、第二行为执行策略，各自去掉首尾空白。
  - 查询子进程的环境去掉 `PSExecutionPolicyPreference`，免得继承父进程临时设的执行策略，查到的不是用户平时窗口的策略。
  - 输出的解析拆成 `shellrc._parse_powershell_query(text) -> Optional[(路径, 执行策略)]`，由下面的查询函数调用。
  - 查询封装成 `shellrc._query_powershell(host) -> Optional[(路径, 执行策略)]`，`host` 取 `"powershell"` 或 `"pwsh"`。找程序也在这个函数里：程序不存在（5.1 的程序文件不存在、`pwsh` 找不到）或查询失败时返回 None，调用方跳过该宿主。测试只替换这一个函数。
- **代价**：
  - 每开一个终端多运行一次 multi-claude，实测约 0.08 秒（2026-11-05 在本机和编译机各测 3 次）。
  - 原本没有初始化补全系统的 zsh 用户，每次还要多执行一次 `compinit -i`。2026-11-05 本机实测：第一次要建立补全缓存，约 0.22～0.32 秒；之后每次约 0.03～0.04 秒。

## 5. 方案

### 5.1 实现要点

1. **`shellrc.py`**
   - `detect_shell(environ)`：Windows 返回 `powershell`；其它系统取 `environ.get("SHELL")` 的文件名，结果在 `completion.SHELLS` 里才有效，否则返回 None。
   - `targets(shell, uninstall, auto)`：返回该 shell 要处理的文件列表。
     - zsh、bash、fish 只有一个文件，位置见 §3 的表。
     - PowerShell 返回本机装了的每个宿主的 `$PROFILE`（查询方法见 §3）。查询每个宿主超时 10 秒；一个宿主都查不到时，报错退出 1。
     - `uninstall` 与 `auto` 都为真时（install.sh 卸载用），不论 `$SHELL` 是什么，都返回 zsh、bash（`.bashrc` 与 `.bash_profile` 两个）、fish 的全部候选文件。这样换过 shell 的用户，旧配置文件里的块也会被清掉。
   - `block_for(shell, exe)`：返回 §3 中的块文本，`exe` 按 §3“绝对路径的取法”得到。
   - `install(shell, auto)` 与 `uninstall(shell, auto)`：返回每个文件的 `(状态, 路径, 提示)`。
     - 状态取值：`installed / updated / unchanged / present / skipped / skipped-off / removed / absent`。
     - 提示用于旧快照和用户自己的 fish 文件这两种情况。
   - **块的读写**：
     - 按行查找成对的开始和结束标记。只有开始没有结束、或出现多个块时，视为文件已损坏：报错退出 1，不改文件。
     - 替换或删除块时，其它行保持不变。追加块时，原文件结尾没有换行就先补一个；原文件非空时，在块前空一行。
     - 删除块时，紧挨在块前的那一个空行一并删掉，反复安装、卸载不会让空行越积越多。原文件结尾没有换行时，追加时补的那个换行在卸载后保留。
     - 删除块后文件只剩空白时，保留这个文件。fish 文件的处理见 §3。
   - **多个文件**：逐个处理。某个文件失败（编码认不出、块损坏、读写出错）时，打一行 error，其余文件照常完成；只要有一个失败，最后退出 1。
     - 读写、备份、编码、权限、符号链接都按 §3 处理。
2. **`cli.py`**
   - 打印、`--install`、`--uninstall` 三种用法互斥；`--auto` 用 `help=argparse.SUPPRESS` 隐藏。
   - 不带 `--install` / `--uninstall` 而又没给 shell 时，报 `completion: choose a shell (bash, zsh, fish, powershell) or use --install`，退出 2。
   - 每个文件输出一行，写到 stdout，格式统一为 `completion: <状态> <路径>`：
     - 新装或更新时，行尾加 ` (open a new terminal)`；
     - 有说明时（present、skipped、旧快照）再输出一行 `completion: note: <说明>`，同样写到 stdout；
     - 失败时向 stderr 输出 `error: completion: <路径>: <原因>`。
   - `--uninstall --auto` 遇到 absent 的文件不输出。
   - 不检查配置文件以外的旧快照文件（如 bash-completion 目录或 zsh fpath 里的）。块在启动时最后注册，会覆盖它们；README 写明这些旧文件可以删除。
3. **`install.sh`**
   - 选项解析增加 `--no-completion) NO_COMPLETION=1; shift ;;`，默认 `NO_COMPLETION=0`。
   - 环境变量读法写作 `[ "${MULTI_CLAUDE_NO_COMPLETION:-}" = 1 ] && NO_COMPLETION=1`，因为脚本开了 `set -u`（`install.sh:13`），变量未设置时直接引用会让脚本退出。
   - 结尾在 PATH 提示之后、`--config` 之前执行。CLI 输出的行原样打出，不加 `[multi-claude-install]` 前缀：

```sh
if [ "$NO_COMPLETION" -eq 0 ]; then
  MULTI_CLAUDE_BIN="$WRAPPER" "$WRAPPER" completion --install --auto \
    || log "note: could not set up tab completion; run: multi-claude completion --install"
fi
```

   - 卸载分支在 `install.sh:88`（`removed=0` 之后、删除程序目录之前）插入以下代码。wrapper 要靠程序目录才能运行，所以必须在删除程序目录之前执行；只有 wrapper 是本安装器写的才执行，与 `install.sh:93` 的判断一致。stderr 丢弃：旧版本的 wrapper 不认识这个参数，会打一段参数错误，失败统一由 note 说明：

```sh
if [ -f "$WRAPPER" ] && sed -n 2p "$WRAPPER" | grep -qF "$MARKER"; then
  "$WRAPPER" completion --uninstall --auto 2>/dev/null || log "note: could not remove the tab completion setup"
fi
```

### 5.2 接口变更

- **新增**：`multi-claude completion --install [SHELL]`、`--uninstall [SHELL]`，以及隐藏的 `--auto`。
  - 退出码：全部文件成功（含 unchanged / present / skipped / skipped-off / absent）为 0；任一文件配置文件读写失败、标记块损坏、编码认不出、查不到 PowerShell 配置文件为 1；参数错误为 2。
- **修改**：`completion` 的 `shell` 参数变为可选。`multi-claude completion <shell>` 的输出不变，向后兼容。
- **新增**：`install.sh --no-completion`、环境变量 `MULTI_CLAUDE_NO_COMPLETION=1`。`install.sh` 默认行为改为会修改用户的 shell 配置文件，需要在 CHANGELOG 中写明。
- **新增状态文件**：`<state_dir>/completion-off`。
- **补全取值不受影响**：`--install` 等是选项而不是取值，`completion.value_spec` 自动从 argparse 读取（`completion.py:64`），`nargs="?"` 不在被拒绝之列（`completion.py:86`）。`completion` 子命令的位置参数取值仍为 `fixed`（`completion.py:23`）。

本方案不涉及 `docs/reference/*`。

## 6. 备选方案与决策

- **在补全目录放快照文件**：每次升级都要重写，而 pipx 和 Homebrew 升级时没有入口去重写，否决。
- **在 bash-completion 目录或 zsh 的 fpath 放一个“现场生成”的小文件**：
  - bash 要求系统装了 bash-completion，macOS 通常没有；
  - zsh 的 `compinit -C` 会缓存补全，新放的文件不生效（2026-11-05 本机实测）。
  - 结论：只有 fish 采用这种做法，其余写配置文件。
- **PowerShell 只写一个宿主**：同时装了 5.1 和 7 的机器上，用户在另一个宿主里没有补全，所以改为本机装了的宿主都写。

## 7. 影响分析

- **install.sh 新行为**：
  - 过去只装程序，现在默认还会改配置文件。
  - 这一步失败只记一条 note，不改变退出码，`--config` 照常执行。
  - 测试环境的 HOME 在临时目录里（`tests/helpers.py:182`），不会碰到真实文件。
  - 测试环境不设 `SHELL`，补全一步只输出“不认识的 shell”提示。`test_install.py:51` 统计 `unchanged` 出现次数的断言要改，只看程序目录和 wrapper 两行，免得以后设了 `SHELL` 后计数变化。
- **与 PATH 提示写同一个文件**：用户照提示把 PATH 设置追加到配置文件时，它会排在块后面。块用绝对路径兜底，所以补全照样生效（§8 第 6 条）。
- **打开终端的代价**：每开一个终端多约 0.08 秒。没有初始化补全系统的 zsh 用户还要加上 `compinit -i` 的耗时，见 §3。命令找不到时，块内的检查让这一段静默跳过。
- **zsh 没有执行 compinit 的用户**：块内会执行 `compinit -i`。`-i` 会跳过不安全的目录且不提问，不会卡住终端；代价是补全系统从此会被初始化，在 CHANGELOG 中写明。
- **已有设置**：
  - 用户自己写的现场生成行：状态为 present，不重复添加。本机和编译机在 2026-11-05 手工加的就属于这种情况；升级后按用户决定先删掉这几行，再执行安装。
  - 旧快照：照常加块，并提示用户删除旧快照。
- **符号链接和权限**：写入真实目标并保持原权限，dotfiles 仓库的链接不会被破坏；备份放在链接旁边，不会在 dotfiles 仓库里多出未跟踪的文件。
- **非 UTF-8 的配置文件**：退出 1、文件不变，提示用户转码。这类文件大多是 Windows 上用 5.1 的 `>>` 或记事本 ANSI 保存的 profile；install.sh 遇到这种情况只记 note，不影响安装。
- **打印用法兼容**：`completion bash|zsh|fish|powershell` 输出不变，CI 现有补全用例照常通过。
- **不新建配置文件的情况**：macOS 上用 `.bash_login` / `.profile` 的 bash 用户，以及执行策略不允许运行脚本、又没有 profile 的 PowerShell 用户，不会自动装上补全，只看到一行说明。这是为了不破坏他们的现有设置、不让打开终端报错。
- **同时用两种方式安装**：用户既用 install.sh 又用 pipx 装了 multi-claude 时，`install.sh --uninstall` 也会删掉补全块，留下的那份安装需要再执行一次 `completion --install`。README 已要求两种方式只用一种（`README.md:108`）。
- **手动用完整路径执行 `--install`、而 bin 目录不在 PATH 上时**：块里没有兜底路径。之后用户把 PATH 设置加在块后面，补全就不生效。install.sh 调用时会设 `MULTI_CLAUDE_BIN`，不受影响；README 写明手动执行前先把 bin 目录加进 PATH。
- **Windows**：只能通过手动执行 `--install`。
  - 写入时保持原文件编码，不经过 PowerShell 的重定向，避开 README 第 152 行提到的 5.1 编码问题。
  - 查询 `$PROFILE` 每个宿主要启动一次 PowerShell（约 1 秒，未实测），只在安装时发生。

## 8. 回归测试

`tests/test_completion_install.py`（POSIX，临时 HOME）：

1. zsh：在已有 `.zshrc` 时写入块，原内容保持不变，并留下 `.multi-claude-bak.*` 备份；再执行一次报 unchanged。
2. `ZDOTDIR` 指向别处时写到 `$ZDOTDIR/.zshrc`。
3. bash：Linux 写 `.bashrc`、macOS 写 `.bash_profile`；块内带 `MULTI_CLAUDE_BIN` 给出的绝对路径。
4. fish：
   - 写入 `completions/multi-claude.fish`，内容为 §3 那一行；
   - 文件是旧快照时，备份后替换；
   - 文件是用户自己的其它内容时，状态为 present、文件不变；卸载也不删除。
5. 现场生成判定：
   - 块外已有 `eval "$(multi-claude completion zsh)"` 时，状态为 present、文件不变；
   - 块外是带 `generated by` 首行的旧快照时，加块并输出删除提示。
6. 实跑检查：对应的 shell 不存在时跳过本用例。
   - PATH 里没有 multi-claude、块里也没有兜底路径时：在交互式 `zsh -f -i`、`bash -i` 中 source 写好的配置文件，没有任何输出，退出码为 0。
   - PATH 设置追加在块之后时：块用兜底路径注册补全，`complete -p multi-claude` 和 `$_comps[multi-claude]` 都有值。
   - zsh 在没有 compinit 的情况下，同样能注册补全。
7. `--uninstall`：
   - 删除块并写入关闭标记；
   - 之后 `--install --auto` 报 skipped-off，文件不变；
   - 不带 `--auto` 的 `--install` 删除标记并重新写入。
8. 损坏的文件（只有开始标记，或有两个块）：退出 1，文件不变。
9. `SHELL` 未设置或不认识：`--install`、`--uninstall` 退出 2，且不生成 `completion-off`；`--install --auto` 退出 0 并打出提示；`completion` 不带任何参数时退出 2。
10. 写入方式：
    - `.zshrc` 是符号链接时，写入后链接仍在，内容写进了链接的目标；
    - 0600 的文件写回后仍是 0600。
11. `SHELL` 未设置时，`--uninstall --auto` 会清理 zsh、bash、fish 全部候选文件里的块，不写关闭标记，已有的关闭标记保留。其中 `.bashrc` 是损坏的文件时，`.zshrc` 的块仍被删除，退出 1。
12. 按字节处理：带 BOM 的 UTF-8、CRLF 换行的 `.zshrc`，写回后仍带 BOM、仍是 CRLF，且没有 `\r\r\n`；GBK 编码的文件、含 NUL 字节的文件都退出 1，文件不变，错误信息里有转码提示。
13. 块的反复写入：
    - 以换行结尾的文件，反复执行三次 `--install` / `--uninstall` 后，与最初的内容逐字节相同；结尾没有换行的文件，卸载后只多出结尾那一个换行；
    - 手动执行 `--install` 时 `MULTI_CLAUDE_BIN` 未设、PATH 里也没有命令：已有块里的兜底路径被沿用，状态为 unchanged。
14. macOS 分支（把系统判断替换为 Darwin）：只有 `~/.profile` 时，bash 状态为 skipped，不新建 `.bash_profile`；配置文件所在目录不存在时（如 fish 的 completions 目录）会先创建。

## 9. 日志 / 观测点

- CLI 每处理一个文件向 stdout 输出一行 `completion: <状态> <路径>`，有说明时再输出一行 `completion: note: ...`；失败时向 stderr 输出 `error: completion: <路径>: <原因>`。
- install.sh 原样打出 CLI 的这些行；补全这一步失败时，输出 `[multi-claude-install] note: could not set up tab completion; ...`。
- 实机核对：新开终端后检查补全是否已注册。
  - zsh：执行 `print $_comps[multi-claude]`；
  - bash：执行 `complete -p multi-claude`；
  - fish：输入 `multi-claude ` 后按 Tab。
